# Wickmail v0.1.0 release notes

Wickmail v0.1.0 is the first MVP release: self-hosted email with programmable,
expiring aliases. An alias grants temporary delivery permission to a primary
mailbox. When the lease expires, mail is quarantined instead of reaching the
inbox, and replies sent from the app keep using the alias so the primary address
stays private.

## Highlights

- **Alias core.** Readable random addresses, case-insensitive canonical lookup,
  a lease model evaluated from stored fields, and lifecycle audit events.
- **Inbound mail path.** Postfix RCPT-time policy lookup, an LMTP proxy that
  strips client `X-Wickmail-*` headers, delivery-time routing, a durable spool,
  and Dovecot Sieve routing to `Inbox`, `Spam`, or `Aliases/Expired`.
- **Quarantine.** Metadata reconciled against the mail store, crash-safe
  recovery and retention, and quotas that delete the oldest eligible messages
  first.
- **Reply as an alias.** Sanitized reply context, provenance-driven identity
  selection, outbound identity enforcement, DKIM signing, and renewal after
  queueing.
- **Management API and web app.** JSON over HTTPS with session and scoped-token
  authentication, CSRF protection, idempotent mutations, and a responsive UI.
- **Android shell.** A secure WebView wrapper with navigation, copy/share, and
  failure handling.
- **Operational hardening.** Backups and a restore/reconciliation drill, a
  Prometheus metrics endpoint with alert rules, deliverability records and a
  verification script, a NixOS deployment guide, and abuse-control verification.

## Known limitations

- **The server package is not built by the flake yet.** `packages.*` is empty;
  provide `services.wickmail.mail.serverPackage` (or an overlay) until packaging
  lands. This is the largest gap for a turnkey deployment.
- **External inbox placement is not automated.** The SPF, DKIM, DMARC, rDNS, and
  TLS records and a verification script ship, but confirming inbox placement
  requires operator-run tests against external providers
  ([deliverability](operations/deliverability.md)).
- **Single user.** v1 is single-user with one primary mailbox. There is no
  multi-user or delegated alias ownership.
- **SQLite only.** The database is a single file on one host; there is no
  PostgreSQL or high-availability path.
- **No general webmail.** The app has a focused reply composer, not a mailbox
  browser.
- **No alias identity selection in external mail clients.** Replies through the
  app preserve the alias; arbitrary IMAP/SMTP clients do not participate in
  identity selection.
- **Metrics require wiring.** The server exposes `/metrics`, but Prometheus and
  an alerting destination are host configuration.
- **Notifications are post-MVP.** No expiring-soon or quarantine notifications.

## Tagging

The maintainer tags `v0.1.0` on `main` after this work is merged. Do not tag from
the feature branch:

```sh
git checkout main
git pull --ff-only
git tag -a v0.1.0 -m "Wickmail v0.1.0: MVP"
git push origin v0.1.0
```

If a release artifact is needed, generate it from the tagged commit. The
annotated tag message references these notes.
